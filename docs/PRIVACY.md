# Защита данных Jarvis

Текущий режим владельца: `JARVIS_MESSAGING_ENABLED=0` скрывает инструменты переписки
из списка модели и блокирует их вызов; `JARVIS_LOCAL_AI=0` и `JARVIS_LOCAL_VOICE=0`
выключают локальные LLM/TTS. Vosk продолжает работать локально. Обычные домашние
запросы получает OpenRouter; музыка VK не использует инструменты личной переписки.

Решение владельца от 05.11.2026: переписка VK/Telegram не передаётся облачным ИИ;
записи диктовки распознаются локально. Это реализовано модулем программы,
а не инструкцией в промпте и не установленным в Codex скиллом.

Перед важной диктовкой скажите «Режим переписки» и дождитесь подтверждения.
Этот режим также включается после распознанной команды чата: неоднозначная
следующая фраза не попадёт облачной модели. Для обычного разговора скажите «Заверши
переписку». Это важно, потому что распознавание намерения по произвольной фразе
не безошибочно. В режиме переписки даже непонятый текст остаётся локальным.

Работают открытие диалогов и отправка явно продиктованного сообщения через саму
платформу. Облачные «черновик по контексту» и «ответь в моём стиле» блокируются
до чтения диалога для облачной модели. В main после RC1 подключён отдельный
локальный модуль: [установка и команды](LOCAL_AI.md). Он может разбирать диктовку
и готовить ответ по стилю локально. Без установленного модуля эти функции остаются
заблокированными. Голос A сохранён для обычных ответов; приватный текст использует
локальный синтезатор, а при его недоступности — Windows, без облачного fallback.

При явной команде «Запомни мой стиль в этом диалоге» сохраняются только выбранные
исходящие примеры локально. Профиль и черновик не попадают в облачный контекст.
Выгрузка модели после простоя не снимает защиту диктовки. Явная команда выхода
очищает приватный контекст и завершает процессы перед обычным облачным диалогом.

Выбранный образец для облачного голоса передаётся TTS-сервису. Не выбирайте
образец с личными сведениями, если не хотите передавать их этому сервису.

Важные границы:

- Локальный Vosk не отправляет запись ASR-провайдерам. Даже при старом
  JARVIS_ASR=openrouter политика по умолчанию оставляет эффективным Vosk.
- Частные команды переписки обрабатываются до вызова модели. Их текст, результат,
  имена и выбранные идентификаторы не добавляются в облачную историю/контекст.
- Результаты messaging tools заменяются заглушками перед сериализацией в запрос
  к модели. Признак приватной речи переносится и через фоновые задачи.
- Известные ключи и очевидные токены удаляются из текстовых запросов.
  Это дополнительный фильтр, не универсальный распознаватель всех секретов.
- Текстовые модели запрашиваются с data_collection=deny и zdr=true. Если
  подходящего маршрута нет, запрос завершается ошибкой; политика не ослабляется.
  Условия ZDR заявляет сервис: сам факт передачи обычного запроса в облако остаётся.
- HTTP-модуль разрешает только заданные HTTPS-сервисы, отклоняет другой origin
  при перенаправлении и не переносит туда Authorization.
- Выделенный браузер VK ограничивает HTTP(S)/WebSocket назначения доменами VK
  и его CDN. Service workers блокируются для работы перехвата; окружение браузера
  не содержит переданных через env API-ключей. VK по-прежнему получает данные
  своего аккаунта, необходимые для работы самой платформы.
- Telegram API соединяется с Telegram для авторизации, чтения и отправки.
  Запрет облачного ИИ не означает, что Telegram/VK могут работать без сети.

Проверки: `Jarvis.exe --privacy-check` (в исходниках `python -m jarvis --privacy-check`).
Они используют вымышленные canary-данные, подставные аккаунты и транспорты:
реальные аккаунты не открываются и запросы в сеть не выполняются. Проверяются
диктовка, история, приватный LLM/TTS, запрет ASR, чужой HTTP и ответ по стилю.
Дополнительный тест настоящего Chromium проверяет блокировку canary-fetch.

`--privacy-report` показывает счётчики решений. privacy-audit.sqlite сохраняет
до 2000 записей только с временем, категорией, решением и типом назначения —
без переписки, аудио, ключей, адресатов и полных URL. Это журнал проверенных путей
программы, а не захват пакетов всех процессов Windows.

JARVIS_PRIVACY_MODE=offline_ai дополнительно запрещает облачные LLM/ASR/TTS.
Свободный диалог ИИ тогда недоступен до подключения локальной модели; локальные
команды продолжают работать. Открытые сайты и сами VK/TG всё ещё используют сеть.

Обычные вопросы, выбранные для обработки документы и код могут передаваться
облачным моделям в strict. Эта политика специально закрывает переписку, диктовку
и учтённые секреты, а не делает весь помощник офлайн. Сессии и настройки остаются
локально в Windows-профиле. assistant.log может содержать локальные фразы —
перед передачей журнала другому человеку удаляйте личную информацию.

Модуль не является системным брандмауэром, антивирусом или изоляцией произвольного
кода. Настроенные проверки кодящего проекта выполняются с правами пользователя:
для недоверенного репозитория нужна отдельная ОС-песочница. Worktree сам по себе
её не заменяет. Абсолютную гарантию отсутствия утечек со всего ПК эти тесты не дают.
