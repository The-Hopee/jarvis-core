# Обновление 0.3: видео, диалоги, голос и кодящие агенты

## YouTube

«Джарвис, открой на ютубе видео Егора Крида» теперь использует поиск видео,
а не разбор доменного имени. Инструменты `search_youtube` и `open_youtube_video`
получают реальные результаты YouTube и открывают конкретный `watch?v=...`.
По описанию без названия выбирается первый результат; можно указать название
ролика или передать `index` от 1 до 5. При недоступности поиска ссылка не выдумывается.

## Telegram API

Обычное «открой Telegram» по-прежнему запускает приложение без API-авторизации.
Для работы с личными диалогами нужен отдельный вход в пользовательский аккаунт:

```powershell
cd C:\Users\tima\jarvis-core
.\.venv\Scripts\python.exe -m jarvis --telegram-login
```

Создайте `api_id` и `api_hash` в https://my.telegram.org/apps. Команда запросит их,
номер телефона, код из Telegram и при необходимости пароль двухэтапной защиты
локально. Данные API сохраняются в исключённом из Git `.env`; сессия — в
`%LOCALAPPDATA%\Jarvis\telegram\user.session`. Во время входа сообщения не отправляются.
Файл сессии и API hash нельзя публиковать. Сессия Telegram Desktop не копируется.

## VK через браузер

```powershell
.\.venv\Scripts\python.exe -m jarvis --vk-login
```

Войдите в VK в открывшемся Chromium, откройте сообщения и нажмите Enter в
терминале. Профиль хранится в `%LOCALAPPDATA%\Jarvis\vk-browser`. Пароль вводится
на странице VK. Рабочий процесс браузера общается с контроллером по отдельному
постоянному каналу JSON Lines. Браузер принадлежит запущенному голосовому помощнику;
при его остановке окно закрывается, авторизация сохраняется.

VK меняет интерфейс: при неподтверждённом диалоге или неизвестных элементах
помощник завершает команду с ошибкой вместо отправки в случайное окно. До входа
пользователя работа с реальным аккаунтом не проверена; браузерная логика проверена
на локальной странице с диалогом и отправкой без сетевого получателя.

## Команды диалогов

- «Джарвис, открой диалог с Петей в телеграмме».
- «Джарвис, открой ВКонтакте диалог с Иваном Петровым».
- «Джарвис, открой диалог с Петей в телеграмме и напиши ему: Привет, буду в пять».
- «Джарвис, прочитай последние сообщения диалога с Петей в телеграмме».
- «Джарвис, открой диалог с Петей в телеграмме и ответь по контексту в моём стиле».

При нескольких совпадениях нужно уточнить имя или Telegram username. Падежи
русских имён нормализуются локально. Источник стиля — только исходящие сообщения
в выбранном диалоге, максимум десять примеров из последних тридцати сообщений.
Для контекстного ответа нужен рабочий OpenRouter. Текст выбранной переписки
отправляется модели по просьбе пользователя; остальная история аккаунта не выгружается.

`open_dialog` и `read_dialog` не отправляют сообщения. `draft_reply` готовит
черновик. `send_message` и `reply_in_my_style` доступны только при прямой просьбе
написать/отправить/ответить в текущем обращении. Для просьбы показать черновик
отправка закрыта. После начала отправки записывается идентификатор операции:
при неопределённом сетевом результате повторная отправка того же обращения
не выполняется. Содержание сообщений в журнале операций не хранится.

## Низкий мужской голос

На текущем компьютере установлен локальный Silero v5 CPU, выбран Eugene:

```dotenv
JARVIS_TTS=silero
JARVIS_LOCAL_SPEAKER=eugene
JARVIS_VOICE_PRESET=deep
```

Голос работает без внешнего сервиса TTS. Это самостоятельный голос с низкой
спокойной подачей, не копия актёра из фильма. Второй вариант — `aidar`.
Образцы находятся в `%LOCALAPPDATA%\Jarvis\voice-previews`. Режимы `normal`,
`deep`, `cinematic` меняют темп; для Edge также используется настройка высоты.
Параметры `JARVIS_TTS_RATE` и `JARVIS_TTS_PITCH` позволяют изменить настройку.

Установка локального голоса на другом компьютере (Python 3.11+ x64):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-voice.ps1
```

Загружаются CPU PyTorch и модель с официального сервера Silero. Модель и её
лицензия описаны в https://github.com/snakers4/silero-models; веса не включены
в Git. Первый запуск загружает модель в память, последующие ответы быстрее.

## Мастер, исполнители и ревью

Реализованы план до четырёх подзадач, зависимости, до двух одновременных
исполнителей, отдельные Git worktree, объединение результатов в ветку
`jarvis/integration/...`, настроенные локально проверки и отдельный вызов модели
для ревью. Каждый исполнитель запускается отдельным Python-процессом и имеет
свою историю диалога. В исходной рабочей папке файлы не меняются; итоговая ветка
и замечания остаются для просмотра. Автоматической отправки результата в GitHub нет.

Инструменты: `list_coding_projects`, `start_coding_task`, `coding_job_status`.
Запуск возможен для проекта из `%LOCALAPPDATA%\Jarvis\projects.json` с заданными
командами проверок. Регистрация своего Git-репозитория:

```powershell
.\.venv\Scripts\python.exe -m jarvis.coding register my-project C:\path\to\repo --checks-json '[["python","-m","unittest","discover"]]'
```

Команды проверок — доверенная локальная конфигурация, аргументы исполняются без
shell. Worktree разделяет изменения файлов, но не является песочницей ОС.
Модель исполнителя получает инструменты чтения/записи в своей рабочей копии и
запуска заданных проверок. `.git`, `.env` и выход за рабочую папку закрыты.

Необязательные модели ролей в `.env`:

```dotenv
JARVIS_MASTER_MODEL=
JARVIS_WORKER_MODEL=
JARVIS_REVIEW_MODEL=
```

Пустое значение использует `OPENROUTER_MODEL`. Двух исполнителей, объединение,
проверки и сохранность исходного checkout проверили на реальном временном Git-
репозитории с тестовыми ответами моделей. Полный прогон с OpenRouter пока
невозможен: текущая авторизация возвращает HTTP 401.

После изменения настроек: `manage.cmd restart`. Для проверки в терминале:
`manage.cmd foreground`, затем Ctrl+C и `manage.cmd start` для возврата в фон.
