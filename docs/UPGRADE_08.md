# Версия 0.8 — профили и скиллы

Команды: «включи лёгкий режим», «включи документный режим», «включи кодящий режим»,
«включи авто», «какой режим?». Выбор сохраняется локально. Фоновые задания получают
снимок режима при постановке в очередь. Префикс «в фоне» доступен для долгих запросов;
кодящие задания всегда идут через очередь.

В авто обычный разговор и бытовые команды используют gpt-4.1-mini, документы —
openai/gpt-6.1-terra low, код и явно сложные рассуждения — openai/gpt-6-sol high.
Это правила по домену и явным признакам, а не безошибочный оценщик сложности:
если выбор не подходит, переключите режим вручную. Модели/effort настраиваются в env.
GPT-6 использует Responses API с сохранением непрозрачных reasoning items между
вызовами tools. Оба профиля проверены настоящим циклом tool → result → ответ.
Terra также создала настоящий DOCX без запуска приложения.

Манифесты скиллов находятся в jarvis/routing.py: system, desktop, web, youtube,
music, weather, messaging, documents, coding. Модель получает только нужные схемы.
Отправка сообщений и запись документов сохраняют отдельные проверки текущей просьбы.
Текст диктуемого сообщения не определяет профиль; включение режима требует отдельной команды.

Локальные лимиты: 0.10 USD/лёгкая реплика, 0.30/документная реплика,
1.00/кодящая задача. SQLite резервирует оценку перед вызовом и учитывает usage.cost;
при обрыве без usage списывает полную оценку. Кодящие процессы делят один бюджет.
Новые неизвестные модели требуют добавления проверенной цены в budget.PRICES.
Эти лимиты учитывают текстовые LLM-вызовы; ASR/TTS оплачиваются отдельно.
Это консервативный локальный учёт по ценам на 05.11.2026, не гарантия счёта провайдера.
Жёсткий общий предел задавайте у API-ключа OpenRouter; текущий предел ключа не изменён.

Проверки: tests/test_routing.py, scripts/responses_smoke.py, scripts/routing_smoke.py;
последние два делают небольшие платные запросы при явном запуске. Аудио не воспроизводят.
