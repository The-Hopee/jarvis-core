# Версия 0.6 — потоковый голос и выбор ASR

Основной OpenRouter-голос теперь декодируется из MP3 в PCM по мере загрузки.
Частота источника определяется MP3-декодером, затем корректно преобразуется
в 24 кГц mono для проигрывателя; скорость/высота голоса не подменяются сменой
частоты воспроизведения. Выбранный образец A сохранён.

Короткий диалог, простая арифметика/определения и реплика после выполненного
открытия приложения могут передаваться из модели потоково: готовое предложение
начинает озвучиваться, пока следующая часть ещё формируется. В таком запросе
вызовы инструментов отключены. Неоднозначные задачи с инструментами сначала
получают полностью проверенные аргументы и результаты; промежуточное обещание
модели не выдаётся за выполненное действие. Простые запросы состояния ПК/погоды
выполняются сразу локальным обработчиком без двух лишних обращений к LLM.

Если сеть оборвётся до начала речи, используется прежний резервный голос.
После частично прозвучавшего потока весь ответ заново не воспроизводится;
текст остаётся доступен. Поток и звуковой выход закрываются при отмене;
блокирующее чтение сети ограничено таймаутом. Статус и ответ не накладываются.
Микрофон во время речи всё ещё закрыт; barge-in эта версия не добавляет.

Параметры (включены по умолчанию):

```dotenv
JARVIS_TTS_STREAMING=1
JARVIS_LLM_STREAMING=1
```

Значение 0 возвращает соответствующий непотоковый вариант. Нужен `av==19.0.2`,
который добавлен в зависимости. Точечные записи из локального voice-pack
воспроизводятся прежним способом.

## ASR: измерение вместо замены по названию

На 32 одинаковых синтетических русских WAV сравнили локальный Vosk,
OpenRouter Scribe v2 и Whisper large-v3-turbo. Микрофон и аккаунты не использовали.
Медиана: Vosk 0,575 с, Scribe 1,186 с, Whisper Turbo 2,524 с. Нормализованный
WER: 6,25%, 1,39%, 4,86% соответственно. Приведение алиасов VS Code/YouTube/
Telegram и числовые различия описаны в scripts/asr_compare.py. Это небольшой
синтетический набор, а не доказательство качества в любой комнате.

Scribe оставлен основным, Vosk — резервным. Потоковые API других сервисов
требуют отдельного ключа; не выдаём файловый HTTP-запрос за живую транскрибацию.
Расширение кандидатов возможно после подключения нужного провайдера.

## Проверки

Настоящий Fish-поток дал первый PCM через 2,532/1,948 с при полной загрузке
3,189/3,307 с в двух тихих пробах. В контрольном запросе состояния ПК первый
PCM поступил в виртуальный проигрыватель через 4,540 с от оценки конца фразы.
Виртуальный выход не означает акустическое измерение. Настоящий RawOutputStream
также проверен одной короткой репликой; она передана аудиодрайверу через
5,604 с от начала TTS-запроса — сетевой первый байт сам занял 5,322 с.
Время облачного провайдера меняется, поэтому гарантии ответа за 2–5 с нет.

Регрессии проверяют декодирование MP3 с ID3 до окончания загрузки, разрыв потока,
отмену, отказ от повторной полной озвучки, SSE без финального маркера, сборку
частичных аргументов tools без исполнения и одновременные интервалы метрик.
Результаты с ограничениями — [VALIDATION.md](VALIDATION.md).
