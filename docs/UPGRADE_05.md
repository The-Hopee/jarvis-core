# Версия 0.5 — измерения и быстрый голосовой отклик

Первый этап [плана выпусков](RELEASE_PLAN.md). Добавлены замеры, короткие
бытовые ответы и кэшированные голосовые статусы. Потоковый основной голос,
новый ASR и общий диспетчер фоновых задач относятся к следующим этапам.

## Как пользоваться

Скажите обычную команду: «Джарвис, состояние машины» или «Джарвис, какая
погода?». Если обработка длится дольше 0,8 с после принятия фразы, помощник
может произнести текущий этап: «Распознаю команду, сэр», «Готовлю ответ, сэр»,
«Выполняю команду, сэр» или «Готовлю озвучивание, сэр».

Статусы не означают завершённое действие. Они выбираются по работающему этапу,
воспроизводятся только из подготовленных файлов, не запускают инструменты и
не делают сетевых запросов. Один этап не объявляется повторно; между репликами
не менее восьми секунд. Быстрый ответ может прийти совсем без статуса.
Статус не накладывается на основной голос: активная короткая реплика завершается,
новые статусы отменяются, затем начинается ответ. Это может добавить остаток
длительности реплики к ожиданию ответа, что видно в замерах. Статусы ограничены
шестью секундами и размером 512 КиБ, обычно подготовленные реплики короче двух
секунд. В режиме --mute или JARVIS_TTS=off голосовых статусов нет.

На текущем ПК четыре реплики уже подготовлены с выбранным пользователем
образцом A. Они находятся в локальном каталоге Jarvis вне Git. Чтобы подготовить
их на другой установке или после смены голоса, выполните один раз:

```powershell
cd C:\Users\tima\jarvis-core
.\.venv\Scripts\python.exe -m jarvis --prepare-status-voice
```

Команда с облачным голосом делает четыре оплачиваемых запроса при первом
запуске для выбранных настроек; повторный запуск использует готовые файлы.
Смена модели/голоса/содержимого образца выбирает отдельный каталог кэша.
Если реплики не подготовлены или файл повреждён, задача продолжится без них;
сетевой синтез статуса во время пользовательской команды не запускается.

Необязательные параметры .env:

```dotenv
JARVIS_PROGRESS=1
JARVIS_PROGRESS_DELAY=0.8
```

Значение 0 отключает статусы; задержка допускается от 0,2 до 10 секунд.
Изменения настроек применяются после `manage.cmd restart`.

## Где смотреть скорость

Обезличенные записи: `%LOCALAPPDATA%\Jarvis\logs\latency.jsonl`.
Файл ограничен 2 МиБ, сохраняются три предыдущих файла. Запись выполняется
один раз после обращения; ошибка записи метрик не повторяет действие.

```powershell
.\.venv\Scripts\python.exe -m jarvis --latency-report --latency-source voice
```

Для текстовых обращений используйте `--latency-source text`; без фильтра
будут показаны все источники с их количеством. В отчёте для каждого показателя
отдельно указаны число измерений, медиана p50 и p95. У обращений из --once
и текстового режима нет этапа микрофона/ASR.

| Показатель | Что измеряет |
| --- | --- |
| endpoint_final_ms | Задержка распознавания окончания фразы относительно оценки её конца |
| asr_ms | Работа облачного уточнения готовой записи; ошибки включены |
| model_ms | Сумма отдельных запросов к модели, включая вложенные вызовы для черновиков |
| tool_ms | Работа инструментов, включая ожидание их сетевых/вложенных операций |
| tts_ms | Подготовка голоса, включая неудачный провайдер и резервный синтез |
| feedback_start_ms | Начало воспроизведения первого локального статуса |
| answer_ready_ms | Готовность содержательного текста |
| tts_first_byte_ms | Первый байт HTTP-ответа голосового сервиса |
| answer_playback_start_ms | Передача основного ответа проигрывателю |
| playback_ms | Воспроизведение основного ответа; отдельно от подготовки голоса |
| status_playback_ms | Воспроизведение всех статусов |
| turn_end_ms | Время завершения обращения |

В JSON также есть отдельные интервалы каждого обращения к модели и инструмента.
Вложенные интервалы пересекаются: например, инструмент черновика включает
запрос к модели. Их нельзя слепо складывать для получения общего времени.
Первый байт TTS не обязательно означает уже пригодный к воспроизведению звук.
Отметка проигрывателя — программная передача аудио, не акустический замер
момента, когда звук достиг динамика.

Конец речи оценивается по времени последнего слова Vosk и временам захвата
аудио. Источник указан как vosk_word_end_estimate. Это оценка, а не эталонная
ручная разметка голоса. Если времени слов нет или аудиопоток сообщил потерю
данных, используется endpoint_only: отсчёт начинается с готовности локального
распознавания; такую запись нельзя выдавать за полный замер от конца речи.
Отчёт показывает количество записей с каждым источником оценки.

Метрики содержат случайный ID, время записи, имена этапов/моделей/инструментов
и длительности. Тексты команд, переписки, документов, аудио, ключи и аргументы
инструментов в файл метрик не записываются. Прежний журнал консольных реплик
assistant.log существует отдельно и сохраняет своё прежнее поведение.

## Короткие ответы

Модель получает указание отвечать на бытовую команду одним-двумя короткими
предложениями, не пересказывать документ и всю команду. Для простых запросов
состояния ПК/погоды особо длинный успешный ответ заменяется кратким описанием
реальных данных инструмента. Подробный анализ, прогноз, составные просьбы,
черновики, диктуемые сообщения, ошибки и неполные измерения не обрезаются.

Микрофон по-прежнему закрыт во время обработки и речи, чтобы помощник не
распознавал собственные статусы. Продолжение разговора доступно после ответа;
перебивание и приём новой задачи во время текущей работы в 0.5 не реализованы.

## Воспроизводимый эксперимент

Скрипт генерирует 32 заранее заданных синтетических WAV, проигрывает их в
обработчик входа с реальной скоростью, затем вызывает настоящие ASR/LLM/TTS
и воспроизводит ответы. Микрофон не открывается. Состояние ПК измеряет настоящее
C++-ядро; погода/запуск приложения/сайта заменены тестовыми обработчиками.
В скрипте вообще нет инструментов чтения/отправки сообщений и браузера VK.

```powershell
.\.venv\Scripts\python.exe scripts\latency_benchmark.py --live --count 32 --cold 4 --output "$env:LOCALAPPDATA\Jarvis\benchmarks\my-stage05-run"
```

Это оплачиваемый тест с озвучиванием ответов. Нужен новый выходной каталог:
предыдущие замеры не перезаписываются. Во время теста фоновый помощник следует
остановить, чтобы его микрофон не услышал тестовые ответы.

warm означает повторное использование локальных модели Vosk, ядра и Speaker.
cold означает новую загрузку этих объектов/процесса для тех же первых команд,
без перезагрузки ОС и очистки её файлового кэша. Состояние облачных серверов
не контролируется. Это не проверка всего пути холодного запуска Windows.
Время местной инициализации записывается отдельно от времени после фразы.

Для оставшихся cold-повторов без повторения warm-корпуса есть `--mode cold`.
Флаг `--silent` сохраняет реальный облачный синтез, но отключает статусы и
воспроизведение ответа; в таком прогоне нет метрики начала воспроизведения.

Результаты: report.json и timings.jsonl в указанной папке. Эталонные и
распознанные тестовые фразы попадают только в отчёт этого синтетического
эксперимента; файл повседневных метрик остаётся без текста. Реальные VK/TG,
качество на живом голосе пользователя и работа в его комнате проверяются
отдельно. Итоговые числа и проверки версии — в [VALIDATION.md](VALIDATION.md).
