# Джарвис 0.4 — диалог и повседневные задачи

## Беседа

После ответа микрофон снова включается, и 40 секунд можно говорить без «Джарвис».
Ожидание считается после завершения TTS. Таймер настраивается через
`JARVIS_CONVERSATION_SECONDS=0..180`. Помощник обращается на «вы», иногда использует
«сэр», задаёт уместный вопрос после действия и продолжает предыдущую тему.
Пример: «открой вс код» → вопрос о проекте → «да, новый» → обсуждение идеи.
Запуск известных приложений выполняется сразу; модель получает фактический результат
и формулирует одну реплику, без предварительного запроса к модели для выбора app_id.

- «Отбой», «хватит», «пока», «тихий режим» возвращают ожидание имени.
- «Забудь разговор», «новый разговор» или `/reset` очищают контекст текущего процесса.
- «Выход» завершает фоновый процесс; вернуть его: `manage.cmd start`.
- Перебивание ответа, одновременный разговор и потоковая озвучка пока не реализованы.

История ограничена 20 сообщениями. Ссылки на последний выбранный диалог, документ,
видео и приложение хранятся в памяти; через 15 минут без обновления результатов
ссылки истекают. История не является разрешением на отправку сообщений.

«Включи второе» использует уже полученный порядок результатов YouTube. «Напиши ему:
Буду через десять минут» адресует ранее однозначно выбранный диалог. Новое явно
названное имя не подменяется предыдущим адресатом. При нескольких совпадениях можно
назвать кандидата или номер. Только точный ответ на такой выбор в течение двух минут
продолжает исходную просьбу отправить конкретный текст.

## Приложения и Windows

Автоматически находятся запущенные/установленные VS Code и ONLYOFFICE, включая
установку в старом профиле Windows. Переопределения: `JARVIS_VSCODE_PATH`,
`JARVIS_ONLYOFFICE_PATH`. Для Telegram сохранены прежние обнаружение и override.
В реестр приложений попадают конкретные EXE; свободных shell-команд у модели нет.

Примеры: «открой VS Code», «открой вс код», «открой онли офис», «сверни все окна»,
«поставь громкость 30 процентов», «сделай тише», «выключи звук».
Относительная громкость читается непосредственно перед изменением и ограничивается
диапазоном 0..100. Сворачивание не закрывает приложения. Наличие команды Windows
не означает, что отрисовка каждого окна проверена; соответствующие поля результата
это отражают. Реальное сворачивание и изменение громкости оставлены ручной проверке,
чтобы автоматические тесты не меняли рабочий стол/звук владельца.

## Документы ONLYOFFICE

Инструменты: `list_documents`, `read_document`, `create_document`, `fill_document`,
`open_document`. На этом этапе поддерживается файловый DOCX. Инструменты не получают
несохранённый текст активной вкладки и не заполняют произвольные PDF-формы.

Доступные каталоги задаёт `JARVIS_DOCUMENT_ROOTS`, пути разделяются `;`.
По умолчанию это `C:\Users\имя\Documents`. Результаты сохраняются в подпапку `Jarvis`.
Шаблон остаётся исходным файлом, заполнение создаёт копию; совпадение имени результата
завершается ошибкой без перезаписи.

1. «Найди документ заявление» — получить реальный путь.
2. «Прочитай документ заявление.docx» — увидеть поля и содержание.
3. «Заполни шаблон заявление.docx: имя — Иван, город — Дзержинск».
4. «Создай документ с текстом: Список задач на сегодня».

`fields={"имя":"Иван"}` заполняет `{{имя}}` и content controls с tag/alias «имя».
`replacements={"старый текст":"новый текст"}` меняет точные текстовые фрагменты.
Поддерживаются поля в таблицах, колонтитулах и фрагменты, разделённые на несколько
форматированных runs. Форматирование и остальные части пакета сохраняются.
Если хотя бы одно запрошенное поле не найдено, копия не создаётся. Вставленный текст
не рассматривается как новый шаблон и не запускает каскад замен.

Чтение ограничено DOCX до 20 MiB и распакованным пакетом до 80 MiB. Пути проверяются
в Python и независимо в C++: только локальные файлы внутри заданных каталогов,
открываемые зарегистрированным ONLYOFFICE. Создание/заполнение доступно по прямой просьбе.
Короткое уточнение данных может продолжить двухминутную задачу заполнения только
ранее выбранного шаблона; оно не разрешает создание произвольного другого документа.

## Распознавание речи

```dotenv
JARVIS_ASR=openrouter
JARVIS_ASR_MODEL=elevenlabs/scribe-v2
JARVIS_CONVERSATION_SECONDS=40
```

Используется обычный ключ OpenRouter. Vosk локально определяет обращение и границу
реплики; только активированная реплика (не больше 45 секунд) идёт в облачную ASR.
В период продолжения беседы активируется следующая реплика без имени. После отбой/таймаута
снова нужен «Джарвис». Поток микрофона закрывается до сетевого запроса и TTS.
При сбое ASR применяется локальная расшифровка, сетевые попытки приостанавливаются на минуту.
Текст и пунктуация продиктованного сообщения сохраняются после удаления начального обращения.
Vosk всё ещё может пропустить само имя; облако не прослушивает комнату непрерывно.

## Голос

```dotenv
JARVIS_TTS=openrouter
JARVIS_TTS_MODEL=fish-audio/s2.1-pro
JARVIS_VOICE_REFERENCE=C:\путь\к\чистому-образцу.wav
JARVIS_VOICE_REFERENCE_TEXT=Точная расшифровка образца одной строкой
```

Модель синтезирует новые фразы с аудиообразцом. Выбор существующего голоса вместо
образца: `JARVIS_TTS_VOICE`. Не следует передавать смешанные голоса, музыку и монтаж:
модель может перенести фон и артефакты. Точную естественность/сходство оценивает владелец.
При сбое сетевого TTS на минуту используется локальный мужской Silero, затем
Windows, если локальная модель тоже недоступна. Ключи и аудиообразцы исключены из Git.
На данном ПК выбран вариант А из пользовательского архива Jarvis Voice Pack:
15-секундный образец из коротких реплик. TikTok-образец заменён после замечания о фоне.
Архив, WAV и примеры хранятся в `%LOCALAPPDATA%\Jarvis\voice-references\jarvis-soundpack`.
Файл `speech-samples.json` задаётся через `JARVIS_VOICE_SAMPLES`: точное совпадение
всей реплики (с учётом только регистра/пунктуации) воспроизводит исходный WAV/MP3
без запроса TTS. Длинный ответ не заменяется коротким клипом по совпавшему началу.
Новые фразы синтезируются по образцу. Сейчас настроены 12 готовых реплик; озвучивание
ответа на отдельное обращение «Джарвис» использует исходную запись из набора.

Альтернативный прямой ElevenLabs backend требует `ELEVENLABS_API_KEY`, для синтеза
также `ELEVENLABS_VOICE_ID`. `JARVIS_ASR=elevenlabs` и `JARVIS_TTS=elevenlabs` не требуют
использования этого провайдера для остальных функций. По умолчанию в примере `.env`
платные голосовые сервисы отключены; на данном ПК выбран OpenRouter ASR отдельно.

## Подключения и проверка

Следующее дополнение — [музыкальный скилл VK](VK_MUSIC.md): отдельная вкладка,
поиск/проигрывание треков и управление проигрывателем. Авторизованная проверка
настоящей музыки требует входа пользователя в профиль VK.

Telegram API и VK browser из 0.3 сохраняются. Войти локально:

```powershell
.\.venv\Scripts\python.exe -m jarvis --telegram-login
.\.venv\Scripts\python.exe -m jarvis --vk-login
.\manage.cmd restart
```

Без авторизации настоящие личные переписки недоступны. Генерация ответа в стиле владельца
требует рабочего OpenRouter; реальные сообщения в автоматических тестах не отправляются.

`--doctor` показывает выбранные ASR/TTS, наличие ключей (не значения), каталоги
документов и доступность приложений. `--speak "На связи, сэр"` проверяет текущий голос.
`--voice-previews` сохраняет образец текущего облачного голоса локально.

В этой версии исправлена совместимость OpenRouter: `parallel_tool_calls=false` не
передаётся в строгую маршрутизацию, потому что текущий endpoint GPT-4.1-mini не объявляет
поддержку параметра. Выполнение инструментов остаётся последовательным и ограниченным.
Management key не подходит для completions: нужен отдельный inference key.
На данном ПК создан отдельный ключ Jarvis с лимитом $5 без периодического сброса;
исходная локальная конфигурация сохранена в игнорируемом `.env.management-backup-*`.
