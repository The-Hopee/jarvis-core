# Версия 0.7 — фоновые задачи

Примеры:

- «Джарвис, в фоне подготовь документ с текстом: План на завтра».
- «Джарвис, что сейчас выполняется?».
- «Джарвис, статус задачи 3».
- «Джарвис, отмени задачу 3».

Префикс «в фоне» ставится перед заданием; продиктованный текст не изменяется.
Помощник подтверждает приём короткой локальной репликой и снова слушает обращение.
Можно задать другой вопрос, пока задание выполняется. Автоматический выбор
режима/сложности добавляется следующим этапом. Кодящие задачи тоже направляются
в очередь; одновременно выполняется не более одной кодящей задачи, чтобы
осталось место для обычных запросов.

По умолчанию работают два исполнителя, максимум 16 незавершённых задач.
Зависимости и приоритет поддерживаются диспетчером. У каждого задания свои
состояние ассистента, история и разрешения из его исходной просьбы. Старое
разрешение отправить неоднозначному адресату не переносится из ожидающего
выбора в другую фоновую задачу. В фоне лучше задавать самодостаточные задания
с явно названными файлами/адресатами; уточнение через неоднозначное местоимение
не связывает два независимых задания автоматически.

Профиль VK, сессия Telegram, документы и действия рабочего стола имеют общие
блокировки. Задачи с независимыми ресурсами идут параллельно; два изменения
общего ресурса ждут очереди. Один браузерный работник VK разделяется между
контекстами и не закрывается при завершении отдельного задания.

Уведомления произносит основной процесс после закрытия входного потока:
работники не говорят в открытый микрофон. При поступлении уведомления во время
тишины слушатель освобождает микрофон; распознанная начавшаяся фраза имеет
приоритет. Полноценного перебивания речи/AEC по-прежнему нет. После подтверждения
фоновой задачи новое обращение требует имени «Джарвис». При играющей музыке
сохраняется защита от распознавания песен как продолжения диалога.

## Состояние и отмена

```powershell
.\.venv\Scripts\python.exe -m jarvis --jobs
.\.venv\Scripts\python.exe -m jarvis --cancel-job 3
```

Отмена задачи в очереди не запускает её. У выполняющейся задачи сначала
появляется cancel_requested, затем конечное состояние. Между запросами модели,
получением результата и вызовами инструментов проверяется отмена. Пока
неоконченный сетевой запрос не вернулся, отмена может ожидать его таймаута.
Уже выполненные действия/отправленные запросы не откатываются; неизвестная
отправка не повторяется. Собственные кодящие дочерние процессы и тесты при
отмене останавливаются по сохранённому PID вместе с их собственными потомками.
Работник также проверяет жизнь родителя перед новыми действиями.

После перезапуска queued/running/cancel_requested помечаются interrupted /
needs_review. Автоматического исполнения этих записей нет. Нужно проверить
состояние задания и его результатов, прежде чем задавать новую работу.
Остановка фонового помощника также запрашивает остановку его работников.

Данные хранятся в `%LOCALAPPDATA%\Jarvis\jobs.sqlite`, вне Git. В отличие от
обезличенных метрик, здесь есть исходная просьба, нужный контекст и финальный
текст результата. Хранятся последние 500 завершённых задач и все текущие.
Ключи API отдельно, в локальных настройках. Журнал подтверждений отправки
сообщений не удаляется вместе с историей задач.

Текстовый режим поддерживает те же команды. Интерактивный режим и --once
получают единоличное владение помощником; для дополнительного запуска следует
остановить текущий экземпляр. --doctor/--jobs доступны отдельно.

## Проверки

Проверены параллельность двух задач, приоритет доступного обычного задания
перед второй кодящей задачей, зависимости, отмена ожидающего ресурса, запрет
действия по позднему ответу модели, отсутствие повторов после восстановления,
ограничение очереди и остановка настоящего тестового дочернего процесса.
Тихая проверка с реальной моделью/ядром завершила две задачи независимо;
текстовый CLI на изолированном профиле подтвердил приём, уведомление, запрос
состояния и чистый выход. Живые кодящие модели/аккаунты проверяются отдельно.
